# Knowledge: `app/bug-management-ui/webapp/css/idts-shell.css`

## English

### What this file is for

`idts-shell.css` styles the small signed-in profile shell that appears above the protected Fiori Elements app. It supports `IDTS-53`: users must clearly see who is signed in and have a visible Sign Out action.

### Beginner explanation

The main IDTS screen is generated by Fiori Elements. We should not reach into generated internal controls just to add a profile menu. Instead, `index.html` provides a stable host, and `auth-guard.js` renders a small SAPUI5 profile button into that host.

This CSS positions and styles that host. It keeps the profile button floating at the top-right of the browser page without changing the generated List Report/Object Page structure.

### Flow in IDTS

1. `index.html` loads this CSS.
2. `index.html` provides `<div id="idtsProfileShellHost"></div>`.
3. `auth-guard.js` waits for SAPUI5, creates a profile button and popover, and places it at that host.
4. This CSS positions the host and applies spacing/metadata styling to the popover content.
5. On small screens, the profile button content is constrained so it does not occupy too much horizontal space.

### Important source anchors

| Location | IDTS concept | Impact if broken | Must check together |
| --- | --- | --- | --- |
| `#idtsProfileShellHost` | Profile shell anchor | Profile menu may disappear, render in the wrong place, or block popover clicks if pointer events are wrong. | `index.html`, `ProfileShell.js` |
| `.idtsProfileButton` | Signed-in user entry point | User may not notice the account/profile control or may be unable to open it if pointer events are wrong. | `ProfileShell.js` Button |
| `.idtsProfilePopoverContent` | Profile popover layout | Name/email/role/sign-out area may become cramped. | `auth-guard.js` ResponsivePopover |
| `.idtsProfileEmail`, `.idtsProfileRole`, `.idtsProfileExpiry` | Profile metadata readability | User profile details may not have clear visual hierarchy. | Public user profile from `srv/auth.js` |
| `@media (max-width: 37.5rem)` | Mobile shell behavior | Profile button may cover too much of the app header on small screens. | Browser responsive smoke |

### Cross-folder impact

- No direct backend dependency exists, but the displayed user data comes from the safe public user object returned by `srv/auth.js`.
- `ProfileShell.js` must keep the class names used here when it renders the profile button and popover.
- `index.html` must keep `idtsProfileShellHost`; otherwise this CSS has no render target.

### Safe editing checklist

- Do not style or select generated Fiori Elements internal IDs.
- Keep the shell as a lightweight overlay; do not turn this into a second navigation system.
- Prefer SAP theme variables for colors and shadows.
- Verify that the profile button is visible after login and does not block critical app actions.
- Verify sign out still clears session and redirects to `login.html`.

## IDTS-54 update - dashboard responsive styling

### English

IDTS-54 adds lightweight dashboard classes in this same shell CSS file:

- `.idtsDashboardPage`
- `.idtsDashboardTiles`
- `.idtsDashboardTile`

These classes only control spacing, max width, and tile width. They do not override Fiori Elements generated internals.

Important anchor:

- Location: `.idtsDashboardTile` and mobile media query
  - IDTS concept: dashboard KPI tiles must wrap cleanly on desktop and mobile.
  - Impact if broken: the dashboard can become too wide, cramped, or hard to scan.
  - Must check together: `dashboard-page.js` tile layout and browser responsive smoke.

### Vietnamese

IDTS-54 thêm một số class nhẹ cho dashboard ngay trong file shell CSS này:

- `.idtsDashboardPage`
- `.idtsDashboardTiles`
- `.idtsDashboardTile`

Các class này chỉ điều chỉnh spacing, max width và độ rộng tile. Chúng không override internal generated control của Fiori Elements.

Anchor quan trọng:

- Vị trí: `.idtsDashboardTile` và media query mobile
  - Khái niệm IDTS: KPI tile của dashboard phải tự wrap tốt trên desktop và mobile.
  - Ảnh hưởng nếu sai: dashboard có thể quá rộng, chật, hoặc khó scan.
  - Phải kiểm tra cùng: layout tile trong `dashboard-page.js` và browser responsive smoke.
