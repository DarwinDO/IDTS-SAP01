### English

`similarBugReviewFieldLabel` and `classificationReviewFieldLabel` are concise labels for custom fields placed inside the existing Bug Summary and Classification forms. They replace long helper sentences that did not fit a standard Fiori Form cell.

## English

### What this file is for

Internationalization resource bundle for the Fiori app. Contains English (and base) texts for app title, descriptions, button labels, dialog titles, and transaction helper texts.

### IDTS flow

Fiori uses these keys for UI labels, action buttons (Create Bug, etc.), and default headers.

Key IDTS-specific entries include texts for "Create Bug", "New Bug", various annotation helper defaults, and the custom History Timeline section.

### Cross-folder

Used by manifest (i18n model), annotations, and custom XML fragments.

Changes here affect all visible text in List Report and Object Page.

### Important source anchors

- `historyTimelineTitle` / `historyTimelineNoData`
  **IDTS concept**: Labels the custom grouped history section and its empty state.

- `historyTimelineShowDetails`, `historyTimelineField`, `historyTimelineOldValue`, `historyTimelineNewValue`
  **IDTS concept**: Provides translated labels for expanding raw audit log details under a grouped history event.

## IDTS-43 update - Create Bug and History wording

### English

IDTS-43 adds/uses `createBug=Create Bug` for the custom role-aware List Report action and changes `historyTimelineTitle` to display simply as `History`.

This file only stores UI text. The visibility and behavior of the `Create Bug` button live in `manifest.json` and `BugListActions.js`. The title change supports the UX decision to show one clear History section instead of making users compare a "History Timeline" label with another generated "History" table.

Important anchor:

- Location: `createBug` and `historyTimelineTitle`
  - IDTS concept: clear labels for the bug creation entry point and audit/history section.
  - Impact if broken: The button or section can show missing i18n keys or inconsistent wording.
  - Must check together: `app/bug-management-ui/webapp/manifest.json`, `app/bug-management-ui/webapp/ext/actions/BugListActions.js`, `app/bug-management-ui/annotations/object-page.cds`, and `app/bug-management-ui/webapp/ext/fragment/HistoryTimeline.fragment.xml`.

### Vietnamese

IDTS-43 thêm/dùng `createBug=Create Bug` cho custom action tạo bug theo role trên List Report, đồng thời đổi `historyTimelineTitle` để hiển thị ngắn gọn là `History`.

File này chỉ lưu text UI. Việc nút `Create Bug` có hiện và chạy thế nào nằm trong `manifest.json` và `BugListActions.js`. Việc đổi title hỗ trợ quyết định UX: chỉ hiển thị một section History rõ ràng, thay vì để user phải phân biệt "History Timeline" với một bảng generated "History" khác.

Điểm neo quan trọng:

- Vị trí: `createBug` và `historyTimelineTitle`
  - Khái niệm IDTS: label rõ ràng cho điểm tạo bug và section audit/history.
  - Ảnh hưởng nếu sai: Button hoặc section có thể hiện key i18n bị thiếu hoặc wording không đồng nhất.
  - Phải kiểm tra cùng: `app/bug-management-ui/webapp/manifest.json`, `app/bug-management-ui/webapp/ext/actions/BugListActions.js`, `app/bug-management-ui/annotations/object-page.cds`, và `app/bug-management-ui/webapp/ext/fragment/HistoryTimeline.fragment.xml`.

## IDTS-94 review-decision copy

### English

`aiSuggestionReviewUnavailable` is the safe empty/error state when no persisted audit ID can be reviewed. `handoffSummaryReviewNotice` explains that a review decision cannot change the Bug or create comment/history. `smartAssignReviewNotice` explains that reviewing explanations cannot select or assign a developer.

### Vietnamese

`aiSuggestionReviewUnavailable` là empty/error state an toàn khi không có audit ID để review. `handoffSummaryReviewNotice` nói rõ quyết định review không đổi Bug và không tạo comment/history. `smartAssignReviewNotice` nói rõ review explanation không chọn hay assign developer.
