# Knowledge: `srv/notification/scheduled.js`

## English

This module is the N4 technical scheduler boundary for Pending Assignment SLA and Overdue discovery. `processNotificationSchedules(req)` accepts only the CAP `OutboxProcessor` scope and ignores arbitrary client filters; the server supplies the current timestamp when the action does not provide one. `discoverScheduledNotifications({ tx, now })` reads only open Pending Assignment or past-due Bugs in bounded pages of 500, resolves active PM recipients for assignment/SLA events, and resolves active current-action owners plus distinct technical assignees for Overdue events.

The existing `writeNotificationRecord()` is the single transactional producer. It inserts one source-keyed `Notifications` event, one personal inbox index row, and—only for Critical/Blocker Pending Assignment or SLA—one prompt email outbox row. Normal SLA reminders and all Overdue events are inbox/digest policy only. Keys `PENDING_ASSIGNMENT:<bugID>:<recipientID>`, `SLA:<bugID>:<threshold>h:<recipientID>`, and `OVERDUE:<bugID>:<dueDate>:<recipientID>` make schedule repeats no-ops; a changed due date creates a new Overdue cycle. The module never sends email or calls the existing `processEmailOutbox` worker.

Pending Assignment SLA age uses the Bug's latest managed `modifiedAt` (falling back to `createdAt`) as the persisted status-touch anchor because the current Bugs model has no separate status-entered timestamp. Critical/Blocker is due at four hours and other priorities/severities at 24 hours. Overdue compares the date-only due date to the fixed run date and excludes `CLOSED` Bugs. A CAP action transaction owns the writes, so a source/inbox/delivery failure rolls back the schedule transaction instead of leaving partial state.

## Tiếng Việt

Module này là boundary scheduler kỹ thuật của N4 để discovery SLA Pending Assignment và Overdue. `processNotificationSchedules(req)` chỉ nhận scope CAP `OutboxProcessor` và bỏ qua filter tùy ý từ client; nếu action không truyền timestamp thì server dùng thời điểm hiện tại. `discoverScheduledNotifications({ tx, now })` chỉ đọc Bug đang Pending Assignment hoặc đã quá due date theo page bounded 500, resolve PM active cho event assignment/SLA, và resolve current action owner active cùng technical assignee khác người cho event Overdue.

Module dùng `writeNotificationRecord()` hiện có làm producer transactional duy nhất. Hàm này insert một event `Notifications` có source key, một row inbox cá nhân và—chỉ với Pending Assignment hoặc SLA Critical/Blocker—một row email outbox prompt. SLA mức thường và mọi Overdue chỉ theo policy inbox/digest. Các key `PENDING_ASSIGNMENT:<bugID>:<recipientID>`, `SLA:<bugID>:<threshold>h:<recipientID>` và `OVERDUE:<bugID>:<dueDate>:<recipientID>` khiến schedule chạy lại thành no-op; đổi due date tạo cycle Overdue mới. Module không gửi email và không gọi worker `processEmailOutbox` hiện có.

Tuổi SLA Pending Assignment dùng `modifiedAt` managed mới nhất của Bug (fallback `createdAt`) làm mốc status-touch vì model Bugs hiện chưa có timestamp riêng cho lúc vào status. Critical/Blocker đến hạn sau bốn giờ, priority/severity khác sau 24 giờ. Overdue so sánh due date chỉ lấy phần ngày với ngày chạy cố định và loại `CLOSED`. Transaction của CAP action sở hữu các write, nên lỗi source/inbox/delivery rollback cả schedule transaction thay vì để state dở dang.

## Safe editing / Sửa an toàn

Keep the module source-only and scheduler-only: do not add a new worker/provider, broaden the candidate predicate, email normal reminders/Overdue, expose raw recipient/provider fields, or merge discovery into `processEmailOutbox`. / Giữ module chỉ source và scheduler: không thêm worker/provider mới, mở rộng predicate candidate, gửi email reminder thường/Overdue, expose field recipient/provider thô hoặc gộp discovery vào `processEmailOutbox`.
