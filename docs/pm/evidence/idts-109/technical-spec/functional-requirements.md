# Functional Requirements — Candidate

These rows describe business outcomes. Source paths, handlers, HTTP requests and
database details belong in Technical Implementation, not in the requirement text.

| Number | Business requirement | Actor | Precondition | Outcome | Related feature |
| --- | --- | --- | --- | --- | --- |
| 1 | The system shall allow an active IDTS user to sign in securely and access only the functions permitted for the user's role. | Tester, Developer, PM | The user has an active account and valid credentials. | An authenticated session is established and the protected application opens. | Authentication and session management |
| 1.1 | The system shall show the signed-in user's safe profile information and allow the user to sign out. | Tester, Developer, PM | The user has an active authenticated session. | Profile information is shown without sensitive authentication data; signing out ends the session and returns the user to Sign In. | Profile and logout |
| 2 | The system shall provide a role-aware dashboard that highlights the bugs and actions relevant to the signed-in user. | Tester, Developer, PM | The user is signed in and can read bug data. | The user sees role-specific counts and attention items without receiving additional write authority. | Dashboard |
| 2.1 | The system shall allow a PM to monitor open work, pending assignment, overdue bugs and developer workload. | PM | The PM is signed in and monitoring data is available. | The PM can identify workload and follow-up needs using read-only monitoring information. | PM monitoring |
| 3 | The system shall record in-application notifications for business events that require another user to act. | Tester, Developer, PM | A valid bug workflow or collaboration event has committed. | The intended recipient can see the event and its related bug context. | In-app notifications |
| 3.1 | The system shall track email-delivery attempts independently from the committed bug workflow. | System worker, PM observer | A notification and eligible email-delivery row exist. | Delivery is recorded as sent, failed or skipped; an external delivery failure does not undo the bug update. | Email outbox and delivery monitoring |
| 3.2 | The system shall allow an authorized user to post a non-empty comment on an active Bug, attributed to the authenticated user. | Tester, Developer, PM | The Bug is active and has no unsaved edit draft. | The comment is persisted, displayed in the Bug comment feed and represented in audit/notification side effects without trusting client-supplied author data. | Bug collaboration comments |
| 3.3 | The system shall allow an authorized user to upload, download and delete Bug evidence through the standard attachment capability, subject to file-size, media-type, persistence and storage rules. | Tester, Developer, PM | The target Bug context is accessible and the selected file satisfies the configured restrictions. | Attachment metadata remains associated with the Bug, binary content uses the configured storage adapter, and the UI reflects the committed attachment state. | Bug evidence attachments |
| 4 | The system shall provide optional AI-assisted suggestions that a human can review without automatically changing a bug. | Authorized Tester, Developer or PM depending on the function | The bug context required by the selected assistance function is available. | A safe, reviewable result or an explicit unavailable state is returned; normal manual work remains possible. | AI assistance |
| 4.1 | The system shall require an authorized human decision before a persisted AI suggestion can affect classification or duplicate relationships. | Tester or PM | A current persisted suggestion exists and is eligible for review. | Review status is recorded; only a separately confirmed accepted suggestion may update allowed business data. | AI review, apply and confirm |
| 4.2 | The system shall provide PM-only operational AI metrics without exposing prompts, provider responses, secrets or raw error details. | PM | Sanitized AI audit data exists for the selected time window. | The PM receives aggregate request, outcome, review and latency metrics. | AI operational monitoring |
